# Execution plans

Use a tracked plan for changes that span multiple areas, affect deployment, or require product decisions. Small fixes can use a concise plan in the issue or pull request.

Create active plans in `active/` and move them to `completed/` when shipped.

Each plan should include:

- Problem and business outcome
- Users or jobs to be done
- Expected behavior
- Acceptance criteria
- Technical approach and affected files
- Edge cases and failure recovery
- Security, observability, and deployment risks
- Test cases
- Rollout and rollback
- Decision log and progress

Name plans `YYYY-MM-DD-short-title.md`. Keep them updated as implementation changes.
